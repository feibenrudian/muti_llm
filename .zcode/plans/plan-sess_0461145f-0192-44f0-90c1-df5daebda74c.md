# T30 调用日志详情：换裁判模型重新聚合（保留所有裁判输出）

已确认的产品决策：**原始 Trace 记录不动**（最终响应/状态保持客户端当时收到的结果）；重跑 Prompt **按当前配置重新渲染**（原始 messages + 已存成员答案 + Pipeline 当前模板）。重跑只追加新版本，不重调成员。

## 后端

### 1. 新文件 `backend/app/rejudge_svc.py`（仿 logging_svc 的服务模块）
- `RejudgeRejected(Exception)`：携带 `status` 与 `message`，由路由层转 HTTPException。
- `async def rejudge_trace(session, *, trace: RequestLog, judge_model_id: int, fernet_key: bytes) -> ModelCallLog`：
  - 校验（拒绝即抛 RejudgeRejected）：`trace.status == "pending"` → 409（尚在进行中）；`trace.pipeline_name` 为空（透传）或无 `role="member" and status="success"` 的行 → 409（无可聚合的成员答案）；`judge_model_id` 对应模型不存在/停用/其 provider 停用 → 422。
  - 重建裁判调用（复用 `strategies/council.py` 的纯函数）：
    - `answers = [(行.upstream_model_id, 行.response_content) for 成功成员行]`（按 `list_model_calls` 的发生顺序）；
    - 模板：`find_pipeline_by_name(trace.pipeline_name)` 取当前 `judge_prompt_template`，Pipeline 已删或模板为空 → `DEFAULT_JUDGE_TEMPLATE`；
    - `render_judge_prompt(模板, trace.request_messages, answers)`；
    - 参数 `merge_params(新裁判.default_params, trace.request_params)`，再 `build_call_request(新裁判.upstream_model_id, [{"role":"user","content":prompt}], merged, stream=True)`；
    - `build_adapter(新裁判的 provider, fernet_key, timeout/retries 取 merged 的 timeout_seconds/max_retries，默认 120/1)` + `adapter.complete()`（与运行时裁判同一路径，决策 D8 流式聚合）。
  - 落库：成功/失败都 `record_call(role="judge_rerun", ...)` 追加一行（失败时 status=failed + error_message，仍保留为一次可查看的尝试）；**不写 RequestLog**。
- `orm.py:133` role 注释更新为 `member | judge | judge_rerun | passthrough`。无任何表结构变更（D2：create_all 免迁移，清理/详情接口按 request_id 自动覆盖新行）。

### 2. `backend/app/admin/traces.py` 新端点
- `POST /api/admin/traces/{trace_id}/rejudge`，body 为本地 Pydantic 模型 `RejudgeBody{judge_model_id: int}`（仿 playground 的写法）；trace 不存在 → 404；`RejudgeRejected` → 对应状态码。
- 响应 `{"call": row_to_dict(新行)}`；裁判调用本身失败时仍返回 200（`call.status="failed"`），HTTP 错误仅用于校验类拒绝。

## 前端

### 3. `frontend/src/lib/api.ts`
- `api.traces.rejudge(id, judgeModelId)` → `post<{ call: TraceCall }>(.../traces/${id}/rejudge, ...)`（`TraceCall.role` 本就是 string，无需改类型）。

### 4. `frontend/src/lib/trace.ts`：`toTimeline` 分组
- 新 entry 形态：`{ kind: "judge"; calls: TraceCall[] }` —— `role` 为 `judge`/`judge_rerun` 的行合成一组（原始裁判在前、重跑按时间序追加，插在首个裁判行位置）；member/passthrough 保持逐行 `{ kind: "call" }`。透传/失败 trace 无裁判组，行为不变。

### 5. `frontend/src/pages/TraceDetail.tsx`
- 裁判组渲染为一张卡：单版本标题仍为「裁判调用」（兼容既有 e2e 选择器），多版本显示「裁判聚合（N 个版本）」。
- 版本切换 pill 行（多版本时）：`原始 · <model>` / `重跑1 · <model>` …，默认选中最新一版；选中版本沿用现有 actions（模型名/状态/耗时/tokens）与入参/输出折叠渲染。
- 卡体顶部工具行：`Select`（启用模型，label 为 `display_name（upstream_model_id）`，本地小函数实现避免跨页面耦合）+ `Button`「换裁判重新聚合」；`useMutation` 调 `api.traces.rejudge`，loading 用 isPending，失败用 ErrorText，成功后 `invalidateQueries(["trace", id])`。
- 吸顶导航：单版本标签 `裁判 · model` 不变，多版本为 `裁判 · N 版`。
