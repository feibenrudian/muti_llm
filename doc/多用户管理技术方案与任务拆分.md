### 0.2 方案总览（一图）

```
                     浏览器（管理台 SPA）
                            │  ①登录 → 会话令牌（sessionStorage）
                            │  ②管理请求 Authorization: Bearer <会话令牌>
                            ▼
┌───────────────────────── FastAPI 单进程 ─────────────────────────┐
│ 中间件（按路径前缀分流，D26）                                     │
│   /v1/*        → 数据面：用户 Key / 兼容 Key → Caller           │
│   /api/admin/* → 管理面：会话令牌 → 管理员 Caller（auth/login 白名单）│
│─────────────────────────────────────────────────────────────────│
│ 网关（llm_gateway / namespaces）                                 │
│   model 解析 → 授权校验（authz，T49）→ 执行 → 归属落库（T48）      │
│─────────────────────────────────────────────────────────────────│
│ 管理 API：auth（T46）/ users+keys+grants（T47/T49）/ traces+stats│
│─────────────────────────────────────────────────────────────────│
│ SQLite：users / user_api_keys / user_grants / admin_sessions      │
│         + request_logs ∪ model_call_logs 增 user_id/user_username │
└──────────────────────────────────────────────────────────────────┘
```

客户端（OpenAI SDK）视角完全不变：`base_url` 指向本服务，`Authorization` 换成发给自己的用户 Key。

## 1. 关键设计决策（D25–D34）

| # | 决策 | 理由 |
| --- | --- | --- |
| **D25** | **身份显式穿参，不靠请求上下文**：中间件解析身份为 `Caller`（frozen dataclass，`app/auth_svc.py`），写入 `request.state.caller`；`execute_chat`/`_run_pipeline`/`_passthrough`/各流式路径与 detached persist **显式接收 `caller`**，与既有 `client_ip`/`t0` 同款穿参。 | 断连续跑（detached persist）在后台任务里运行、无 `Request` 对象，必须靠参数携带身份；显式穿参也便于 UT 打桩（不依赖 ASGI 环境）。 |
| **D26** | **两个平面共用 `Authorization: Bearer`、按路径前缀分流**，令牌空间互不通用：数据面 = 用户 Key/兼容 Key；管理面 = 会话令牌。管理面错误结构沿用既有 `{"detail": ...}`（HTTPException 风格），数据面沿用 OpenAI error 结构。 | 前端 `req()` 与 Playwright 只需"加一个头"，无需 Cookie/CSRF/CORS 配置；`{"detail"}` 与既有管理 API 错误形态一致（前端 `parseErrorMessage` 已兼容两种）；Bearer 头与浏览器 Cookie 罐无关，Playwright 的 `request` fixture 与浏览器上下文不共享 Cookie 的坑自动规避。 |
| **D27** | **归属由调用行显式穿参**：`logging_svc.start_request/record_call` 增 `user_id: int = 0, user_username: str = ""`，由 `caller` 逐层透传；**不从父行反查**（少一次查询、无隐式耦合）。rejudge 从原 `RequestLog` 行取归属。 | 与 D25 同源；`record_call` 调用点 8 处（含 2 处 detached persist），穿参与既有风格一致。 |
| **D28** | **兼容 Key 走零查询短路**：bootstrap 返回并缓存 `app.state.admin_user_id`；认证先做常量时间哈希比对（命中即 `Caller(via="legacy")`，不查库），未命中再查 `user_api_keys.key_hash`。 | 既有部署的全部数据面流量零额外查询；比对顺序把常见路径放在最前。 |
| **D29** | **测试基建用"客户端默认头"注入管理会话**：`asgi_client`/`backend_live` 默认 `Authorization` = **直插库**铸造的会话令牌（不跑 PBKDF2、不走登录端点），`/v1` 用例按既有 `auth_headers(service_key)` 逐请求覆盖。 | 后端测试有 **177 处** `/api/admin` 调用点（21 个文件），逐处加头不可接受；httpx 允许逐请求同名头覆盖默认头，既有 `/v1` 断言零改动。 |
| **D30** | **口令迭代数进配置**：`settings.pbkdf2_iterations`（默认 600,000，环境变量 `MUTILLM_PBKDF2_ITERATIONS`），AE conftest 调低（如 1,000）。 | 每次用例 lifespan 都要为内置 admin 生成口令哈希；600k 迭代 ≈ 0.3s × 200 用例 ≈ 60s 纯等待，必须可调。生产默认仍满足 NFR-8。 |
| **D31** | **`last_used_at` 节流写**：每 Key 每 60 秒至多一次 UPDATE（进程内 `{key_id: monotonic}` 记账，随请求会话提交）。 | 认证在热路径上，逐请求 UPDATE 是纯写放大；节流后精度对运营完全够用。 |
| **D32** | **授权判定"一次装载"**：`load_scope()` 一次查询取该用户全部授权行 → `AccessScope(pipeline_ids, model_ids, provider_ids)`，列表过滤与调用判定共用同一对象；管理员短路为 `unrestricted`（**零查询**）。 | 授权即时生效（NFR-10 不做缓存）且单请求只付一次查询；管理员路径零查询保证"响应与现状逐字节一致"（AC-MU-6）。 |
| **D33** | **授权行随被授权对象删除级联清理**（模型/供应商删除路径追加清理），查询侧仍按存在性兜底（防御历史遗留）。 | 避免脏行累积；不依赖 polymorphic 外键（SQLite 无法声明）。 |
| **D34** | **统计扩展只加维度、不改口径**：复用 `_aggregate_columns()` 与 `_stats_filters()`，`user` 筛选按 `ModelCallLog.user_id`（整数）匹配，用户名仅用于展示；新增 `by-user`、`by-user-model` 两个分组端点。 | 与 T41 既有实现对账口径完全一致（列求和 = 端点结果），不引入第二套算法。 |

## 2. 数据模型与迁移

### 2.1 新增表（`app/orm.py`，沿用 `utcnow`/`UTCDatetime`/`JSON` 惯例）

```python
class User(Base):
    __tablename__ = "users"
    id: int (PK)
    username: str(32) unique                       # 登录名，创建后不可改
    display_name: str(50)
    role: str(10) default "user"                   # admin | user
    enabled: bool default True
    password_hash: str(200) default ""             # PBKDF2-HMAC-SHA256 hex；一般用户为空（D23）
    password_salt: str(64) default ""
    remark: str(500) default ""
    created_at / updated_at (UTCDatetime)

class UserApiKey(Base):
    __tablename__ = "user_api_keys"
    id: int (PK)
    user_id: int → users.id（index）
    name: str(50) default ""                       # 标签：家用笔记本 / 脚本 …
    key_hash: str(64) unique                       # sha256(明文)
    key_encrypted: Text default ""                 # Fernet 副本：掩码展示 + 主动复制
    enabled: bool default True
    created_by: int default 0                      # 操作管理员 id（审计：谁发的 Key）
    last_used_at: UTCDatetime | None (nullable)    # 节流写（D31）
    created_at: UTCDatetime

class UserGrant(Base):
    __tablename__ = "user_grants"
    __table_args__ = (UniqueConstraint("user_id", "kind", "target_id"),
                      Index("ix_user_grants_user_id", "user_id"))
    id: int (PK)
    user_id: int → users.id
    kind: str(10)                                  # pipeline | model | provider
    target_id: int                                 # 按 kind 指向 pipelines.id / models.id / providers.id
    created_at: UTCDatetime

class AdminSession(Base):
    __tablename__ = "admin_sessions"
    id: int (PK)
    token_hash: str(64) unique                     # sha256(令牌)；明文不落库
    user_id: int → users.id（index）
    created_at / expires_at / last_seen_at (UTCDatetime)
```

### 2.3 迁移与语义

- 建表由 `Base.metadata.create_all` 完成（新表自动带上 ORM 声明的索引）；补列/补索引幂等（D2：不引入 Alembic）。
- **历史行语义**：`user_id = 0` 且 `user_username = ""` → 展示"（历史）"；用户筛选（`user_id` 整数匹配）天然不命中它们（需求 FR-22）。
- **无回填**：不给历史行猜归属（多用户之前的调用在事实层面无归属），保持诚实。
- **删除语义**：删用户 → 级联删 `user_api_keys` / `user_grants` / `admin_sessions`（`repos.py` 新增 `delete_user_cascade`）；日志表不删（冗余用户名快照保留，D22）。删模型/供应商 → 清理同 `kind` 的授权行（D32）。
- **兼容 Key 不建"影子行"**：仍存于 `app_settings`（`service_api_key_hash` / `service_api_key_encrypted`），Key 列表接口把它合成为一条只读特例行（`is_legacy=true`，`id=0`）。

### 3.2 `app/auth_svc.py`（新文件）

### 3.3 中间件改造（`app/main.py`，单中间件双分支）

现状：`require_service_key` 只处理 `/v1/` 前缀、只比对一把哈希。改造为：

```python
@app.middleware("http")
async def authenticate(request, call_next):
    path = request.url.path
    token = _bearer(request)                       # 复用现有解析
    if path.startswith("/v1/"):
        result = await auth_svc.resolve_data_plane_identity(request.app, token)
        if isinstance(result, AuthError):
            return openai_error(result.status, result.message, code=result.code)  # 数据面结构
        request.state.caller = result
    elif path.startswith("/api/admin/") and path not in ADMIN_AUTH_WHITELIST:
        result = await auth_svc.verify_session(...)                        # 需 DB session
        if isinstance(result, AuthError):
            return JSONResponse({"detail": result.message}, status_code=result.status)
        request.state.caller = result
    return await call_next(request)
```

**数据面解析顺序（D28）**：

1. `token` 为空 → 401 `invalid_api_key`；
2. 与 `app.state.service_api_key_hash` 常量时间比对命中 → `Caller(admin_user_id, "admin", "admin", None, "legacy")`（**零查询**）；
3. 否则 `sha256(token)` 查 `user_api_keys.key_hash`（唯一索引）：
   - 未命中 / `key.enabled=False` → 401 `invalid_api_key`（不区分，避免泄露 Key 是否存在）；
   - 命中且 `key.enabled=True` 但 `user.enabled=False` → 403 `user_disabled`（Key 持有人即账号本人，直接告知更可行动，需求 FR-20）；
   - 命中 → `Caller(user.id, user.username, user.role, key.id, "key")`，并按 D31 节流更新 `last_used_at`。

**管理面会话校验**：

- 令牌 → `sha256` 查 `admin_sessions`；未命中/过期 → 401 `{"detail": "未登录或会话已过期"}`；
- 会话有效 → `users.enabled` 且 `role == "admin"`，否则 403 `{"detail": "需要管理员权限"}`（非 admin 角色的判定为 P2 自助门户预留）；
- 滑动续期：`expires_at = now + 24h`，`last_seen_at = now`（管理面流量低，逐请求落库无压力）。
- 白名单：`POST /api/admin/auth/login`、`POST /api/admin/auth/logout`（登出容忍无效令牌 → 幂等 200）。

**`/v1` 身份贯通**：`chat_completions` / `pipeline_chat` / `route_chat` 从 `request.state.caller` 取出并显式传入执行路径（D25）；`playground_run` 构造 `Caller(admin_id, admin_username, "admin", None, "playground")`。

### 3.4 `app/authz.py`（新文件，T49）

> 1.2 未规划该文件：授权判定是数据面领域规则（供网关与未来的自助门户复用），非 HTTP 路由，故与 `auth_svc.py` 平级。

```python
@dataclass(frozen=True)
class AccessScope:
    unrestricted: bool                    # 管理员
    pipeline_ids: frozenset[int]
    model_ids: frozenset[int]
    provider_ids: frozenset[int]

    def allows_pipeline(self, pipeline_id: int) -> bool
    def allows_model_row(self, model_row) -> bool          # model_ids 命中 or provider_ids 命中
    def allows_dynamic(self, provider_id: int) -> bool     # 库内无记录的动态模型 → 仅供应商级

async def load_scope(session, caller) -> AccessScope

def filter_pipelines(scope, pipelines) -> list
def filter_models(scope, models) -> list
def visible_provider_ids(scope, providers, models) -> set[int]   # /v1/route 列表口径
```

**判定矩阵（需求 FR-19）**：

| 入口 | 判定 |
| --- | --- |
| 老入口 Pipeline 名 | `allows_pipeline(pipeline.id)`（成员/裁判不再单独校验） |
| 老入口真实模型名 | 解析出的 `model_row` → `allows_model_row` |
| `/v1/pipeline/chat/completions` | 同老入口 Pipeline |
| `/v1/route/{ident}/chat/completions`（库内启用行） | `allows_model_row` |
| `/v1/route/{ident}/chat/completions`（动态行 `id=0`） | `allows_dynamic(provider.id)` |
| `/v1/models` | Pipeline 与模型分别过滤（叠加接入开关 + `enabled`） |
| `/v1/route` | `visible_provider_ids`：供应商级授权，或该供应商下存在被授权模型 |
| `/v1/route/{ident}/models` | 上游列表 ∩ 授权（动态模型看供应商级）；供应商不可访问 → 404 |

- **管理员短路**：`unrestricted=True` 时全部过滤函数直通、不查授权表（D32）→ 响应与升级前逐字节一致。
- **已知边界（记录不修）**：同名 `upstream_model_id` 存在于多个供应商时，老入口解析取"首个启用行"（既有语义），授权按该行判定；精确到供应商的解析留给 P2。

### 3.5 错误契约总表

| 场景 | 平面 | HTTP | body |
| --- | --- | --- | --- |
| 无/错/停用/删除的 Key | 数据面 | 401 | OpenAI error，`code=invalid_api_key` |
| Key 有效但用户被停用 | 数据面 | 403 | OpenAI error，`code=user_disabled` |
| 模型存在但未授权 | 数据面 | 403 | OpenAI error，`code=model_not_authorized`，message 含模型名 + "请联系管理员开通" |
| 供应商/命名空间不可访问 | 数据面 | 404 | 既有 `model_not_found` / `route not found`（按可见性，与停用同形） |
| 模型不存在/已停用 | 数据面 | 404 | 既有形态（不变） |

## 5. 管理 API 设计

### 5.1 认证（T46，`app/admin/auth.py`）

```
POST /api/admin/auth/login     {username, password}
     → 200 {token, expires_at, user:{id, username, display_name, role}}
POST /api/admin/auth/logout    → 200 {ok: true}（白名单，幂等）
GET  /api/admin/auth/me        → 200 {id, username, display_name, role, expires_at}
POST /api/admin/auth/password  {old_password, new_password} → 200 {ok: true}
```

- 登录：查 `users`（`username`）→ 未启用/口令不符 → 401 统一文案；成功 → `create_session`。
- 改密：校验旧口令 → 更新盐与哈希 → **吊销该用户其他会话**（保留当前会话）。

### 5.2 用户 / Key / 授权（T47 / T49，`app/admin/users.py`；Pydantic 模型入 `app/schemas.py`）

```
GET    /api/admin/users?keyword=&role=&enabled=&page=&page_size=
       → {items:[UserOut], total}
       UserOut = {id, username, display_name, role, enabled, remark,
                  key_count, last_activity_at, created_at}
POST   /api/admin/users   {username, display_name?, role?, remark?, password?}
       → 201 UserOut（role=admin 时 password 必填）
PATCH  /api/admin/users/{id}   {display_name?, enabled?, remark?, role?} → UserOut
POST   /api/admin/users/{id}/password  {new_password} → {ok: true}      # 管理员重置
DELETE /api/admin/users/{id}  → 204                                     # 级联删 Key/授权/会话

GET    /api/admin/users/{id}/keys → [KeyOut]
       KeyOut = {id, name, masked, enabled, is_legacy, created_by, last_used_at, created_at}
POST   /api/admin/users/{id}/keys {name} → 201 {id, name, api_key}      # 明文仅此一次
GET    /api/admin/users/{id}/keys/{key_id}/secret → {api_key}           # 掩码行"复制"用（Fernet 副本）
PATCH  /api/admin/users/{id}/keys/{key_id} {name?, enabled?} → KeyOut
DELETE /api/admin/users/{id}/keys/{key_id} → 204                        # 兼容 Key 行 → 409

GET    /api/admin/users/{id}/grants → {pipelines:[id], models:[id], providers:[id]}
PUT    /api/admin/users/{id}/grants {pipelines:[...], models:[...], providers:[...]}
       → 同 GET 形态（覆盖式；target 不存在 → 422；清空传空数组）
```

规则与校验：
- `username`：`^[a-zA-Z0-9._-]{3,32}$`，全局唯一（重名 → 409）；`display_name` 1–50；口令 ≥ 8 位（重置/提升同规则）。
- **防自锁**（FR-17）：停用/降级/删除前检查"剩余启用管理员数 ≥ 1"，违反 → 409 + 明确文案；内置 `admin` 额外不可删/不可停用。
- **Key 明文交付**：创建响应返回明文一次；`/secret` 端点回显明文（**与 `settings/service-key` 同款既有先例**：AGENTS.md 的"只回掩码"约束针对上游供应商 Key）。
- **兼容 Key 特例行**：`GET .../keys` 在 admin 的列表首位合成 `{id: 0, name: "兼容 Key（旧服务 Key）", masked: <service_api_key 掩码>, enabled: true, is_legacy: true}`；PATCH/DELETE 该行 → 409（提示到设置页重置）。
- `last_activity_at` = 该用户全部 Key 的 `last_used_at` 最大值：一次 `GROUP BY user_id` 聚合查询，不做 N+1。
- 用户列表分页默认 20（与 traces 一致）。

### 5.3 Trace / 统计扩展（T48 展示、T50 筛选与聚合）

```
GET /api/admin/traces?…&user=<用户名或 user_id>        # 数字 → user_id 精确；否则 user_username 精确
    列表项与详情：row_to_dict 自动带出 user_id/user_username（无需改序列化）
GET /api/admin/stats/overview|daily|by-provider|by-model?…&user=<id>
GET /api/admin/stats/by-user?start&end&provider&model
    → [{user_id, user_username, ...既有 metrics...}]
GET /api/admin/stats/by-user-model?start&end
    → [{user_id, user_username, provider_name, model_id, upstream_model_id, display_name, ...metrics...}]
```

- 复用 `_aggregate_columns()`/`_metrics_row()`/`_stats_filters()`（D34），排序统一 `-total_tokens` 优先。
- `user_id=0` 分组即"（历史）"（前端展示层映射文案）。
- CSV 导出沿用前端实现（BOM + CRLF + 引号转义），新增"按用户/按用户×模型"两张表的导出入口。

## 10. 风险与备注

1. **归属断链是本方案最大风险面**：网关侧落库点为 `record_call` 6 处（`_record_outcomes` 汇总点、`_passthrough` 成败两处、`_detached_passthrough_persist` 两处、`_passthrough_stream` 一处）+ `start_request` 2 处（`_run_pipeline`/`_passthrough`），另有 `rejudge_svc`/`admin/traces` 的 6 处走"原 trace 继承"（不穿参）。漏一处即出现"无归属"行。对策：T48 用 UT-48-3 覆盖全路径；AE-48-2 抽查跨路径；并约定"新增任何落库路径必须同时传 `caller`"写入 `logging_svc` 模块 docstring。
2. **口令迭代数不随哈希串存储**：调整 `pbkdf2_iterations` 会让既有口令失效（需管理员重置）。单机工具可接受；若将来要平滑，参考 PBKDF2 的 `$algo$iter$salt$hash` 编码格式（本期不做）。
3. **管理员短路的字节级一致性**：AC-MU-6 要求管理员路径与升级前响应逐字节一致。对策：`unrestricted` 时过滤函数**直通原列表**（不重建、不重排序），AE-49-5 用既有断言口径验证。
4. **测试默认头是"魔法"**：`asgi_client` 默认带头会掩盖"忘记带凭证"的用例。对策：conftest docstring 显式说明 + "未登录 401" 类用例强制显式覆盖（`headers={"Authorization": ""}`）；UE 侧仍走真实登录页，不依赖默认头。
5. **Playwright 与登录态**：新增登录页后，既有 spec 的 seed 必须先登录；`request` fixture 不共享浏览器 Cookie（本项目用 Bearer 头，天然规避），但**令牌要在每个 spec 的 `beforeEach` 或 storageState 中准备好**，否则 e2e 全红。
6. **`user` 筛选的两种写法**：数字视为 `user_id`、非数字视为用户名精确匹配——用户名恰好为纯数字时会产生歧义；用户名校验规则允许纯数字（`^[a-zA-Z0-9._-]{3,32}$`）。对策：筛选先按 `user_id` 命中、未命中再按用户名（两者取并集），并在文档与 UI 提示中注明；如需彻底消除歧义，可后续引入"用户名不得为纯数字"的约束（本期不做）。
7. **P1 的锁定为进程内计数**：多进程/重启后失效；单机单进程（uvicorn 单 worker，`service.sh` 现状）下满足需求；若将来多 worker 需迁到 DB 或 Redis（记录不修）。
8. **`admin_sessions` 无定期清理**：过期会话行会累积（管理面流量低，量级可忽略）；在启动清理逻辑中顺带删除 7 天前的过期会话行（并入 T46 或 T51，成本一行 SQL）。
9. **快照复用依赖"载荷逐字节一致"**：新增用例若不小心改变参数（如给裁判设了 `temperature`），该用例会快照未命中并给出候选 hash 列表——按 SRS 报错定位即可，**不要**为了让它通过而手改快照。
