## 1. 背景与目标

### 1.1 背景

当前服务是"单 Key 单租户"形态：

- 数据面 `/v1/*`（老入口 + T42 的 pipeline/route 命名空间）统一用**一把服务自身 API Key** 认证（FR-4），认证通过即可调用全部"启用且对外开放"的模型——无法区分调用人，也无法限制某人只能用某几个模型。
- 管理面 `/api/admin/*` **不做认证**（tech-plan 决策 D5：本地工具 + "管理 UI 默认仅监听 127.0.0.1" 的简化）。而启动脚本 `service.sh` 现已默认监听 `0.0.0.0` 以支持局域网访问，无认证的管理面不再可接受。
- 用量统计（T41）只有供应商 / 模型 / 天三个维度（`model_call_logs`），**没有用户维度**——多人共用时无法回答"谁用了多少"。日志表只有 `client_ip`，且 IP 在 NAT/局域网下不指向具体人。

要在小团队内共用一台聚合网关，必须补齐：**按人发 Key、按人限模型、按人算用量**。

### 1.2 目标

| 编号 | 目标 |
| --- | --- |
| G-MU-1 | **用户与角色**：引入管理员（admin）与一般用户（user）两类角色；管理台仅管理员可登录使用。 |
| G-MU-2 | **用户级 API Key**：每个用户可持有多把 Key；Key 决定调用身份；可独立创建/停用/删除，停删即时失效；Key 明文仅创建时展示一次，此后掩码 + 复制。 |
| G-MU-3 | **模型访问授权**：管理员按"虚拟模型（Pipeline）/ 供应商 / 模型"三类给用户授权，默认拒绝、即时生效；管理员不受授权表约束。 |
| G-MU-4 | **权限内可见可用**：`GET /v1/models` 及两个命名空间的列表/说明端点只返回该 Key 可访问的模型；越权调用返回明确的"无权限"错误而非静默失败。 |
| G-MU-5 | **用量可归属**：每次对外请求与每次上游调用都记录归属用户；Trace 列表与用量统计都能按"用户 × 时间段 × 模型"查询与导出。 |

### 1.3 非目标（本期不做）

- **配额 / 限流 / 计费**：本期只做"看得清"，不做"限得住"（按 Key 配额计费仍留在 requirements.md §10 未来扩展）。
- **一般用户自助门户**：本期一般用户**只消费 /v1 数据面**，无登录入口、无自助页；其 Key 由管理员代发代管。自助门户（查看自己的 Key 与用量）为 P2 候选（§12.3），设计上预留（见 D23）。
- **组织层级**：用户组/部门/团队、自定义角色、审批流、OAuth/LDAP/SSO 均不做；角色固定两种。
- **多租户隔离**：所有用户共用同一套 Provider / 模型 / Pipeline 配置与同一份上游供应商 Key；不按用户隔离上游凭据、不隔离配置可见性。
- **内容级隔离**：管理员可见全部用户的 Trace 全文（既有语义，此处明确写入避免歧义）；不做"用户只能看自己的 Trace"。
- **Key 过期与自动轮换**：不做有效期/自动轮换（P2 候选）。

### 1.4 术语（增量）

| 术语 | 定义 |
| --- | --- |
| **管理员（admin）** | 管理台的全部权限（配置 Provider/模型/Pipeline、查全部 Trace、管理用户）+ 数据面全部模型的调用权；不受授权表约束。 |
| **一般用户（user）** | 只能通过自己名下的 API Key 调用被授权的模型；无管理台访问权。 |
| **用户 API Key** | 绑定某一用户的 Bearer 凭据（前缀 `sk-mu-`），同时决定调用身份与权限集合；一个用户可有多把。 |
| **兼容 Key（旧服务 Key）** | 多用户之前的历史服务 Key：继续有效，认证后身份 = 内置 `admin` 用户（保证既有部署零改动）。 |
| **授权（Grant）** | 管理员给用户授予的模型访问权，共三类授权项：虚拟模型（Pipeline）/ 供应商 / 模型，取并集生效。 |
| **归属（Attribution）** | 请求日志与上游调用日志上的用户维度（`user_id` + 用户名快照），用于按用户统计与 Trace 追溯。 |
| **管理员会话** | 管理台登录后的访问凭据（会话令牌），只用于 `/api/admin/*`，与数据面 Key 完全分离。 |

| 服务设置（日志保留、接入开关、服务 Key 重置） | ✅ | ❌ |

| 能力 | 管理员 | 一般用户 |

## 3. 关键设计决策（D17–D24）

| # | 决策 | 理由 |
| --- | --- | --- |
| **D17** | **双平面认证，互不通用**：数据面 = 用户 Key（Bearer）；管理面 = 管理员会话令牌（Bearer，登录换取）。两者会话/凭据不得互换使用。 | 数据面 Key 会分发给客户端软件（可被复制）、管理面令牌只存在于浏览器；混用会放大泄露面。分开后"给某个客户端发 Key"绝不等于"给出管理权限"。 |
| **D18** | **权限模型 = 三类授权项取并集，默认拒绝**：`pipeline`（虚拟模型）/ `provider`（该供应商全部模型，含上游新增动态模型）/ `model`（单个模型行）。管理员不受授权表约束。 | ① 供应商级授权是**必需的**：route 命名空间允许调用"上游有、库内无记录"的动态模型（T42），这类模型没有本地行可授权；② 模型级授权覆盖精确场景；③ Pipeline 与真实模型是两类不同的对外入口，分开授权最直观。 |
| **D19** | **越权调用返回 403 `model_not_authorized`**（不存在/已停用仍是 404）。 | 列表端点已按权限过滤，成员知晓模型名通常来自团队共享；"存在但无权，请联系管理员开通"远比误导性的 "model not found" 可行动。命名空间/供应商级不可见仍走 404（按可见性处理）。 |
| **D20** | **Key 形态沿用服务 Key 既有口径**：前缀 `sk-mu-`；认证只比对 SHA-256 哈希；同时用 Fernet 存一份可解密副本，供**掩码展示 + 一键主动复制**（明文仅在创建响应出现一次）。 | 与 `settings/service-key` 的既有实现完全同形（bootstrap.py：哈希认证 + 加密副本用于展示），不引入新机制；"只回掩码"的既有约束针对上游供应商 Key，用户 Key 需要可复制（Key 由管理员代发，必须能交付）。 |
| **D21** | **兼容 Key 归入内置 admin 用户**：身份 = `admin`，权限不受限，用量归属 admin；设置页"服务 Key"卡与重置流程保持不变；在 admin 的用户 Key 列表中以只读特例行展示。 | "已配置服务零改动"是本项目反复出现的立场（T42/T43 同款）；同时避免"admin 名下没有任何 Key 却仍在工作"的解释成本。 |
| **D22** | **归属是两个日志表的冗余列**：`request_logs.user_id/user_username` + `model_call_logs.user_id/user_username`（用户名快照），统计直查 `model_call_logs`，删用户后统计仍完整。 | 与 T41 决策一致（`provider_name`/`upstream_model_id` 同样冗余存储），保证"模型/供应商/用户被删后统计不残缺"；也让统计端点无需 join 用户表。 |
| **D23** | **一般用户本期无登录凭据**（`password_hash` 可为空）；**提升为管理员时必须设置初始密码**。 | 不制造"没有登录入口却有密码"的冗余状态；P2 开放自助门户时再为一般用户补密码即可（表结构已就位）。 |
| **D24** | **归属只进日志、不进上游载荷**：用户身份作为日志元数据落库，不改变发往上游的请求体，也不改变既有响应结构。 | 快照回放是本项目测试体系的地基：上游载荷逐字节不变 ⇒ 全部既有快照零漂移、零重录，回归成本仅为测试前置（登录会话）。 |

## 4. 功能需求

### FR-17 用户与角色管理 【P0】

- 用户字段：`username`（登录名，全局唯一，创建后不可改）、`display_name`（显示名/昵称，可改）、`role`（`admin` | `user`）、`enabled`、`remark`、创建/更新时间；管理员账号另有密码（见 FR-21）。
- `username` 规则：`^[a-zA-Z0-9._-]{3,32}$`（与 Pipeline 命名的严格风格一致）；`display_name` 1–50 字符。
- **内置管理员**：首次启动自动创建 `username=admin`（`role=admin`），不可删除、不可停用、不可降级。
- **防自锁不变量**：系统任何时刻至少存在一名启用状态的管理员——最后一名启用管理员不可被停用/降级/删除（接口拒绝并说明原因）。
- 管理员能力：创建用户、编辑显示名/备注、停用/启用、删除、提升为管理员（提升时必须设置初始密码）、重置管理员密码。
- 停用用户：其名下全部 Key 立即失效（见 FR-20 错误语义），可恢复；删除用户：级联删除其 Key 与授权，**日志与统计保留**（归属显示删除时的用户名快照）。
- 用户列表：用户名/显示名/角色/状态/Key 数量/创建时间/最后活动时间；支持用户名关键字搜索与角色/状态筛选；排序稳定（默认创建时间倒序）。

### FR-18 用户 API Key 管理 【P0】

- 每个用户可持有多把 Key（轮换、多设备/多用途各一把）；Key 字段：`名称`（标签，如"家用笔记本""脚本"）、`状态`、`创建人`（操作管理员）、`创建时间`、`最后使用时间`。
- 新建 Key：响应返回**完整明文一次**（前端弹窗展示 + 复制，关闭后不可再查明文，与设置页重置服务 Key 的交互一致）。
- 列表展示：掩码（`****尾4`）+ 一键复制（Fernet 副本解密）+ 停用/启用 + 删除；**任何列表/详情接口不得回显完整明文**。
- 停用或删除 Key → **下一次调用立即 401**（无需重启）。
- Key 归属唯一用户、不可转让、不可跨用户复制授权；创建时记录操作管理员（"谁发的 Key"可追溯）。
- **兼容 Key 特例**：既有服务 Key 继续有效（D21），在所属 admin 的 Key 列表中作为**只读特例行**展示（标注"兼容 Key"）：不可删除、不可停用，重置仍走设置页"服务 Key"卡（既有 UE-28-1 / AE-28-3 回归行为不变）。

### FR-19 模型访问授权 【P0】

- 三类授权项，**取并集**生效（D18）：
  1. **虚拟模型（Pipeline）**：允许调用该 Pipeline 聚合入口；**Pipeline 内部成员/裁判模型不要求用户单独授权**（否则"聚合"语义不成立——对外承诺的是一个虚拟模型）。
  2. **供应商**：覆盖该供应商下全部模型——老入口按真实模型名透传、route 命名空间的库内模型与**上游新增的动态模型**（库内无记录）均放行。
  3. **模型**：精确到单个模型行（以 `upstream_model_id` 生效），覆盖老入口透传与 route 命名空间。
- **默认拒绝**：新建用户零授权 → 列表为空、任何调用被拒；管理台提供"全选 / 清空"批量操作与三类分组勾选界面（含"全部虚拟模型 / 全部供应商 / 全部模型"）。
- **即时生效**：授权变更（含撤销）下一次请求即生效，无需重启（校验直查库，不做进程缓存）。
- 授权界面展示全部虚拟模型/供应商/模型（含已停用与已下线的，置灰但可勾选，便于预配置）；**运行期以启用状态为准**：停用项不列出、调用 404，与既有规则一致（授权不绕过启用/接入开关）。
- 管理员不受授权表约束（仍受"启用状态 + 接入开关"约束）。
- 被授权的模型不可用时（模型停用、供应商停用、裁判不可用等），走既有错误与容错语义，不因授权而改变。

### FR-20 数据面：Key 鉴权与权限执行 【P0】

- 认证：`Authorization: Bearer <用户 Key>`；Key 无效/已停用/已删除 → `401 invalid_api_key`（既有形态不变）；Key 有效但**所属用户被停用** → `403 user_disabled`（Key 持有人即账号本人，直接告知状态更可行动）；兼容 Key 命中 → 身份 = 内置 admin。
- **列表过滤**（在既有"接入开关 × 启用状态"之上叠加用户授权；管理员 = 现状全集）：
  - `GET /v1/models`：只返回该用户可访问的虚拟模型与真实模型。
  - `GET /v1/pipeline`、`GET /v1/pipeline/models`：仅授权子集（无授权虚拟模型时返回空列表，200）。
  - `GET /v1/route`：只列出"该用户至少可访问一个模型"的供应商（判定：有该供应商级授权，或该供应商下存在被授权模型）。
  - `GET /v1/route/{ident}/models`：按授权过滤（上游动态模型仅由供应商级授权覆盖）；该供应商对本人不可访问 → `404 route not found`（与不存在/已停用同形，命名空间级按可见性处理）。
- **调用拒绝**：模型/虚拟模型未被授权 → `403 model_not_authorized`，message 含模型名并提示联系管理员（D19）；其余错误语义（400 参数、404 不存在或停用、502 上游失败）不变。
- **归属落库**：全部执行路径——老入口、pipeline/route 命名空间、流式、过程流式（stream_process）、ICE 多轮、工具聚合、Playground——在 `request_logs` 与每条 `model_call_logs` 上写入 `user_id` + `user_username`（D22/D24）。
- Playground（试运行）由管理台发起 → 归属**发起的管理员**。
- Trace 重跑（`rejudge`）→ 归属**原 trace 的用户**：保持"一条 trace 一个归属"不变量，避免同一 trace 内混归属导致"按用户统计"与"按 trace 统计"对不上。
- 启动清理（保留期）与手动清空语义不变，不因归属列引入新逻辑。

### FR-21 管理端认证（管理台登录） 【P0，失败锁定 P1】

- 端点：`POST /api/admin/auth/login`（username + password）、`POST /api/admin/auth/logout`、`GET /api/admin/auth/me`、`POST /api/admin/auth/password`（修改自己的密码）。
- **全部 `/api/admin/*` 需管理员会话**（上述 auth 端点除外）：未认证 → `401`（前端跳登录页）；已认证但角色非 `admin` → `403`（为 P2 的自助门户预留判定）。
- 认证方式：登录成功返回**会话令牌**；前端存于 `sessionStorage`，并随 `/api/admin` 请求以 `Authorization: Bearer <token>` 发送；服务端只存令牌哈希；有效期 24 小时滑动（有活动即续期）；登出立即失效；会话落库，服务重启后仍有效。
- 密码存储：PBKDF2-HMAC-SHA256，per-user 随机盐，迭代 ≥ 600,000（标准库 `hashlib`，不引入新依赖）；密码策略：≥ 8 位。
- 首次启动：为内置 `admin` 生成随机初始密码，在**启动日志中打印一次**（"管理员初始密码：…（仅首次启动打印，请登录后修改）"）；未修改密码前，管理台顶部持续提示。
- 登录失败防护【P1】：同一用户名连续失败 5 次锁定 5 分钟（内存计数，重启清零）。
- 前端：新增登录页；未登录访问任意管理页 → 跳登录；`api.ts` 的请求封装统一处理 401（清会话 + 跳登录）；顶栏显示当前用户名、改密与登出入口。

### FR-22 按用户用量统计与 Trace 归属 【P0（归属与筛选）/ P1（前端看板扩展）】

- 归属列（D22）：`request_logs.user_id`、`request_logs.user_username`；`model_call_logs.user_id`、`model_call_logs.user_username`（冗余，与 `provider_name` 同口径）。索引：两表的 `user_id`。
- 历史数据（迁移前写入的行）：`user_id` 为空 → 列表与统计显示"（历史）"；用户筛选不命中它们（与既有数据不伪归属）。
- Trace 列表：新增**用户列**与 `user` 筛选参数（支持用户名或用户 id）；详情页展示发起用户（历史空值显示"（历史）"）。
- 统计 API（在 T41 四端点基础上）：
  - 既有 `overview` / `daily` / `by-provider` / `by-model` 增加 `user` 筛选参数；
  - 新增 `by-user`：按用户分组（调用数 / 失败数 / 输入 / 输出 / 缓存命中 / 缓存写入 / 总 token）；
  - 新增 `by-user-model`：按**用户 × 供应商 × 模型**分组——直接回答"哪个用户、什么时间段、哪个模型、用了多少"。
  - 时间与筛选语义完全沿用 T41（UTC 天分组、`end` 含当天、筛选可组合）。
- 用户用量口径：该用户请求触发的**全部上游调用** token 之和（成员 + 评论 + 裁判 + 重跑），不区分 role（细分留给 role 维度，本期不加）。
- 前端"用量统计"页：新增"按用户"视图（用户明细表 + 用户 × 模型明细表 + 用户筛选器 + KPI 随筛选联动）；CSV 导出沿用既有实现（BOM + CRLF、中文表头）。
- 用户详情页：展示该用户 Key 的最后使用时间（运营视角："Key 发给谁、是否还在用"）。

## 5. 数据模型（增量概要）

**新增 4 张表**（落地字段以技术方案为准）：

```
users:           id, username(唯一，不可改), display_name, role(admin|user),
                 enabled, password_hash, password_salt, remark,
                 created_at, updated_at

user_api_keys:   id, user_id(→users.id), name,
                 key_hash(唯一，SHA-256), key_encrypted(Fernet 副本，展示/复制用),
                 enabled, created_by(操作管理员 id), last_used_at, created_at

user_grants:     id, user_id(→users.id), kind(pipeline|model|provider), target_id,
                 created_at
                 ── 唯一约束 (user_id, kind, target_id)

admin_sessions:  id, token_hash(唯一), user_id(→users.id),
                 created_at, expires_at, last_seen_at
```

**补列 2 张表**（幂等补列，沿用 D2 无 Alembic 惯例）：

- `request_logs`：`user_id INTEGER NOT NULL DEFAULT 0`、`user_username TEXT NOT NULL DEFAULT ''`
- `model_call_logs`：同上两列 + 索引（`user_id`）

**已有表**：Provider / 模型 / Pipeline / PipelineMember / AppSetting 结构不变；`app_settings` 无需新增键（兼容 Key 仍存于 `service_api_key_hash` / `service_api_key_encrypted`，语义不变）。

**删除语义**：删用户 = 级联删 `user_api_keys` + `user_grants` + `admin_sessions`；日志与统计表**不删**（冗余用户名快照保留，D22）。

## 7. 兼容与迁移

- **旧服务 Key**：继续有效 → 身份 = 内置 admin、全部模型可用；既有客户端（SDK/ChatBox/Dify 等）**零改动**；设置页"服务 Key"卡片与重置流程逐字不变（D21）。
- **旧端点行为**：除新增的授权过滤外，错误码与响应结构不变；**管理员 Key 下的响应与现状逐字节一致**。
- **快照零漂移**（D24）：不改上游请求载荷与既有响应结构 ⇒ 既有全部快照命中率保持 100%，无需 `make record` 重录；新增用例的快照按技术方案录制。
- **旧库迁移**：启动时幂等建表 + 补列（D2），不引入 Alembic；历史日志 `user_id` 空 → 显示"（历史）"。
- **测试基建影响**（业务响应不变，仅前置变化）：
  - AE：`conftest` 增加"管理员会话"fixture，既有用例的管理 API 调用需携带会话；
  - UE：`helpers.ts` 的 seed 走管理 API，需先登录并把会话令牌带上（浏览器内的页面操作仍要真实走登录页，登录页本身有独立 UE 用例）；
  - 快照断言与 `/v1` 数据面断言（用兼容 Key / 用户 Key）不受影响。
- **首次启动体验**：admin 初始密码打印在启动日志一次；管理台登录后提示修改。
